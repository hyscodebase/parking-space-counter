# 차량 수 합산 UI 브라우저 확인

2026-11-03 · 원격 Chrome의 Sites 로컬 프리뷰에서 실제 웹 UI와 기존 v2 모델로 확인했습니다. 휴대폰 폭은 iframe으로 확인했으며 실제 iPhone·Android 기기 시험은 아닙니다.

| 시나리오 | 관찰한 결과 |
| --- | --- |
| 처음 열기 | 사진과 결과가 비어 있으며 고정된 시연 확률·가짜 차량 수 없음 |
| 공개 예제의28개 주차칸 실제 추론 | 차량3·빈자리24·확인 필요1, 화면은 확인된 차량3대와3~4대 범위 표시 |
| 28칸 결과 JSON 저장 | 사진 SHA256·모델 버전/해시·28개 ROI·판정 기준·품질·전처리·소요 시간과 합계 일치 |
| 390px 화면의 사진 촬영 버튼 | capture=environment 입력의 파일 선택 경로로 실제 JPG fixture를 읽음. 물리 카메라 촬영은 미검증 |
| 갤러리 선택 | capture 없는 별도 입력 제공, 새 사진에서 이전 결과와 영역 확인 체크 해제 |
| 390px 화면에서 주차칸 두 개 드래그 | A1·A2가 추가되고 위치·크기 입력과 개수가 갱신됨 |
| 네 칸 영역 JSON 적용 후 분석 | 실제 모델로 차량2대·빈자리2칸·확인 필요0 표시 |
| 동일한 사각형을 A1·A2로 중복 지정한 JSON | 같은 영역 오류 표시, 기존 유효 설정 보존 |
| 회색 PNG와 네 칸 | 모델 추론을 생략하고 확인된 차량0·확인 필요4,0~4대 범위로 안내. 정확히0대로 확정하지 않음 |
| 프로필 저장·다시 선택·삭제 | 테스트 이름으로 저장, 목록에서 재적용, 삭제 후 현재 ROI 유지 |
| 저장된 사진과 비율이 다른 사진 | 촬영 위치와 주차칸을 다시 맞추라는 메시지 표시 |
| 분석 취소 | 진행 중 취소 후 부분 결과를 표시하지 않음 |
| 취소 후 영역 JSON 적용·재분석 | 워커 재시작 뒤 네 칸에서 차량2대로 정상 완료 |
| 320/390/768px 화면 | 각 iframe의 scrollWidth와 clientWidth가 일치, 가로 넘침 없음 |

촬영 버튼은 HTML 파일 입력의 후면 카메라 요청을 사용합니다. 기기·브라우저가 이를 지원하지 않으면 일반 파일 선택기가 열릴 수 있습니다. iPhone의 HEIC 파일은 JPG로 변환해야 합니다. 파일 선택과 촬영한 사진은 앱 서버로 전송하지 않습니다.

이 환경에서28칸 첫 분석은 약28.9초, 네 칸은 약3.6~4.0초였습니다. 이 값은 모바일 성능 측정치가 아닙니다. 초기 모델 다운로드, 기기 CPU와 사진·주차칸 수에 따라 달라집니다.

정확한 차량 수 표시는 모든 칸의 모델 판정이 확정됐다는 의미이며 실제 정답 보장은 아닙니다. [559칸 진단](counting-validation.md)에서는 확신이 높은 오분류도 관찰됐습니다. 각 주차칸에 차량 한 대, 촬영 위치에 맞는 ROI, 영역 밖 차량 제외라는 범위를 유지해야 합니다.

자동 검사는 JavaScript50개와 Python14개를 통과했습니다. 모델 가중치는 기존 v2와 동일합니다. 과거4칸 전용 화면의 확인 기록은 `browser-regression.md`에 별도로 남아 있습니다.
