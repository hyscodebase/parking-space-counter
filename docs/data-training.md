# 주차칸 데이터 준비·학습·평가

현재 앱은 **주차칸별 이진 분류 후 사용 중인 칸을 합산**합니다. 기존 v2 모델을 그대로 사용하며 `0대~10대` 클래스 모델을 새로 학습하지 않았습니다. 주차칸1~100개 지원 기능과 모델의 정확도는 별개입니다.

## 기존 데이터

PKLot UFPR04 주간 사진456장을 공식 `@teachablemachine/image@0.8.3` 라이브러리로 Node CPU에서 학습했습니다. 빈자리228장·사용 중228장이며 각 클래스는 맑음100장·흐림100장·비28장입니다. 내부 가중치 학습386장·내부 검증70장, 별도 날짜의 외부 검증150장·시험150장으로 구분합니다.

`.tm`은 사진과 설정을 담은 학습 전 원본이고 완성 가중치는 모델 ZIP의 `model.json`, `metadata.json`, `weights.bin`입니다. 웹 UI가 응답하지 않아 공식 라이브러리를 직접 실행했으며 웹 UI 학습 완료로 표현하지 않습니다.

## 현장 데이터 준비

고정 카메라의 전체 사진과 각 주차칸의 좌표·차량 유무 정답을 준비합니다. 각 사각형 전체를224×224 RGB로 조정하며 앱도 같은 방식을 사용합니다. 한 칸에 차량 한 대라는 전제를 만족해야 합니다. 촬영 위치·각도·사진 크롭이 바뀌면 좌표를 다시 지정합니다.

`tools/manifest.example.csv`를 실제 파일과 정답으로 바꿉니다. 예제 파일과 좌표는 형식 설명용입니다.

| 열 | 의미 |
| --- | --- |
| image | `--image-root` 내부 이미지 상대 경로 |
| slot_id | 주차칸 고유 이름 |
| label | `empty` 또는 `occupied`; `빈자리`, `사용 중`도 허용 |
| date | 촬영 날짜 `YYYY-MM-DD` |
| sequence | 연속 촬영 묶음 ID |
| x, y, width, height | EXIF 방향 보정 후 사진의 정수 픽셀 사각형 |
| lighting | 직접 확인한 `day` 또는 `night`; 야간·황혼은 주간 학습에서 제외 |

두 클래스 모두에 날씨·그림자·젖은 바닥·차량 종류를 다양하게 포함합니다. 가림이 심해 정답을 확정할 수 없는 사진에 억지로 라벨을 붙이지 않습니다. 사진 복제로 표본 수를 늘리지 않고 원본 경로·촬영일·카메라·날씨·해시·검수 내용을 남깁니다.

## 날짜 분리와 자르기

Python3.10 이상에서 실행합니다.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r tools/requirements.txt
python tools/prepare_dataset.py --manifest data/manifest.csv --image-root data/raw --output data/prepared --seed 42
```

Windows 활성화 명령은 `.venv\Scripts\activate`입니다. 입력·출력은 서로를 포함하지 않는 별도 폴더로 두고 출력은 비어 있어야 합니다. 도구는 경로·라벨·중복·좌표를 검증한 뒤224×224로 자릅니다.

동일 원본 사진의 모든 칸, 같은 날짜, 같은 `sequence`는 한 집합에만 둡니다. 기본 분리는 독립 그룹 기준 검증15%·시험15%·나머지 학습이며 최소3개의 독립 촬영 묶음이 필요합니다. 그룹 크기에 따라 실제 이미지 비율은 달라집니다. 클래스·날씨 수를 맞추려고 날짜 분리를 깨지 마세요.

출력은 `train/empty`, `train/occupied`, `validation/empty`, `validation/occupied`, `test/empty`, `test/occupied`와 연결표 `manifest.csv`, 수량·경고 `summary.json`입니다.

## Teachable Machine 학습

일반 이미지 모델의 두 클래스를 `빈자리`, `사용 중`으로 지정하고 학습 폴더만 넣습니다. 날짜를 분리한 검증 사진으로 모델·판정 기준을 정한 뒤 남겨둔 시험 사진에 적용합니다. 내부 학습 화면의 정확도를 독립 시험 정확도로 대신하지 않습니다.

TensorFlow.js로 내보낸 모델을 앱 설정에서 연결합니다. `.tm`은 **Open project from file → Train Model**로 다시 학습합니다. 학습 원본과 재현 코드는 이 저장소의 `training/`과 `artifacts/`에 있습니다. 압축 해제와 재현 명령은 루트 README에 정리했습니다.

## 가변 주차칸 차량 수 평가

새 현장에서는 별도 날짜의 전체 사진에 **분석할 모든 칸**의 좌표와 정답을 기록합니다. 영역 밖 차량은 정답 수량에도 포함하지 않습니다. 범위를 고정하지 않으면 수량 비교가 달라집니다.

- **칸별 정확도:** 정답을 맞힌 칸의 비율. 확인 필요도 별도로 보고
- **차량 수 일치율:** 대상 칸의 실제 차량 수와 확정 수량이 일치한 사진 비율
- **과다·누락 집계:** 빈 칸을 차량으로 판단한 경우와 차량을 빈자리로 판단한 경우
- **확인 필요와 범위 포함률:** 애매한 칸 비율, 실제 수량이 최소~최대 범위에 들어가는 사진 비율

사용 중7칸·확인 필요2칸은 확정9대가 아니라 `확인된7대`, 범위 `7~9대`입니다. 칸별 오류가 상쇄돼 수량만 맞을 수 있으므로 수량 지표만 보지 않습니다. 같은 사진의 반복 분석은 독립 표본을 늘리지 않습니다.

## 기존4칸 도구 구분

`tools/evaluate.py`는 **A1~A4 정답이 있는 과거4칸 평가 도구**입니다. 슬롯 이름도 A1~A4만 받으며 네 칸이 모두 있을 때만 빈자리 수 지표를 계산합니다. 새 가변 주차칸 JSON의 전체 차량 수 평가 도구로 해석하지 않습니다.

과거 JSON/CSV에는 `frame_id,slot_id,truth,status,confidence,source`가 필요합니다. `source=model`, 사람이 확인한 `truth=empty/occupied`를 사용합니다. `demo`와 정답 없는 행은 제외됩니다.

```bash
python tools/evaluate.py legacy-four-slot-results.json --output evaluation-report.json
python -m unittest discover -s tests -p 'test_*.py' -v
```

기존 전체 사진30장·고정4칸120/120 정답·빈자리 수30/30 일치와 미학습 시점10장·고정4칸37/40 정답은 **과거 고정4칸 결과**입니다. 새100칸 기능의 정확도로 제시하지 않습니다. 모델 카드와 보고서의 조건을 함께 읽습니다.

기존 UFPR04 사진20장의 주석 칸559개로 확대한 추가 진단에서는551/559칸(98.57%)이 맞았고, 확인 필요 없이 차량 수까지 정확한 사진은13/20장이었습니다. 기존 사진을 재사용한 진단이며 새 독립 최종 시험이 아닙니다. [집계 설계](counting-design.md)와 [진단 보고서](counting-validation.md)에 범위·오류·예산 제한을 기록했습니다.

## 품질·출처

단색·암전·과노출은 확인 필요로 처리하고 흐림은 경고합니다. 이 검사는 주차장 여부를 의미적으로 이해하는 모델이 아닙니다. 높은 확률이나 검사 통과가 올바른 주차칸을 골랐다는 보장은 아닙니다. 다른 현장·야간·실제 모바일 기기는 별도 검증합니다.
