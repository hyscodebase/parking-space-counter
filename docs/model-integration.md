# 티처블 머신 이미지 모델 연결

앱은 빈자리·사용 중 두 클래스 모델을 현재 브라우저에서 실행합니다. 기본 학습 모델과 실행 라이브러리는 사이트에 포함됩니다. 사진과 로컬 모델 파일은 앱 서버에 업로드하지 않습니다. 예시 그림과 고정 확률은 화면 동작 설명용이며 실제 모델 평가 자료와 구분합니다.

## 기본 모델로 분석하기

1. ‘기본 모델로 시작’ 또는 ‘AI 모델 연결 → 기본 모델 → 모델 불러오기’를 누릅니다.
2. 실제 고정 시점 주차장 사진을 업로드합니다.
3. A1–A4가 서로 다른 네 주차칸을 감싸도록 영역을 지정하고 확인합니다.
4. 분석을 실행한 뒤 확인 필요 사유와 칸별 확률을 살펴봅니다.
5. 정답을 아는 사진은 ‘분석 기록·평가’에서 네 칸의 실제 상태를 기록합니다.

주차장/카메라별 영역과 판정 기준은 브라우저의 프로필로 저장해 다시 사용할 수 있습니다. 사진 시점이 바뀌면 프로필을 그대로 적용하지 말고 네 칸이 맞는지 확인하세요. 브라우저 저장 공간을 지우거나 다른 기기를 사용하면 로컬 설정과 기록은 함께 이동하지 않으므로 JSON·CSV로 필요한 자료를 내보냅니다.

## 직접 학습한 모델 연결

Teachable Machine 이미지 프로젝트에서 두 클래스 이름을 `빈자리`, `사용 중`으로 학습하고 TensorFlow.js 형식으로 내보냅니다. 모델 URL을 입력하거나 압축을 해제한 `model.json`, `metadata.json`, 모든 `.bin` 파일을 함께 선택합니다. 모델의 클래스 이름이 다르면 빈자리·사용 중에 대응하는 이름을 연결 화면에서 확인합니다.

이 프로젝트의 기본 모델은 공식 `@teachablemachine/image 0.8.3` 라이브러리를 Node CPU 환경에서 실행해 학습했습니다. 웹 학습 화면이 응답하지 않아 실행 환경을 바꾼 것이며 웹 UI에서 학습·내보내기에 성공했다고 기록하지 않습니다. 학습 데이터·파라미터·해시와 평가 범위는 배포된 모델 보고서와 모델 카드에서 확인합니다.

추론용 모델 ZIP에는 `model.json`, `metadata.json`, `weights.bin`이 들어 있습니다. 별도 `.tm` 파일은 웹 학습 화면에서 다시 열 수 있는 원본 학습 프로젝트입니다. 원본 프로젝트에 완성 가중치가 포함되는 것으로 해석하지 마세요. 재학습 프로젝트 묶음의 README에 학습 코드와 데이터 준비 방법이 있습니다.

## 파일과 네트워크

TensorFlow.js와 Teachable Machine Image 라이브러리는 `dist/vendor/`의 고정된 파일을 사용하고, 기본 가중치는 `dist/models/parking/`에서 읽습니다. 외부 CDN에서 실행 라이브러리를 내려받는 구조가 아닙니다. 처음 사이트와 기본 모델을 여는 데에는 해당 사이트에 접근할 수 있는 네트워크가 필요하며, 오프라인 설치를 보장하는 PWA는 아닙니다.

외부 모델 URL을 입력한 경우에만 그 모델 서버에서 JSON·메타데이터·가중치를 읽습니다. 사진은 전송하지 않습니다. 직접 호스팅한 외부 모델은 HTTPS와 브라우저 CORS 접근이 필요합니다. URL에 인증정보를 포함하는 방식은 허용하지 않습니다. 로컬 모델은 모든 가중치 조각을 지원하며 파일 합계는 250MB 이하로 제한합니다.

사이트의 조회 권한은 호스팅 설정을 따릅니다. 팀원에게 링크를 전달하는 것만으로 새로운 조회 권한이 생기지는 않습니다.

## 영역·입력 검사와 판정

주차칸 좌표는 원본 사진 대비 0~1 범위의 `x, y, w, h`입니다. 선택한 사각형 전체를 224×224로 조정합니다. 학습 자료도 같은 자르기 방식을 사용해야 합니다. 완전히 같은 영역을 여러 칸으로 지정할 수 없으며, 크게 겹치는 영역은 경고를 확인해 다시 조정합니다. 회전된 주차칸은 주변 차량이 포함되지 않도록 살펴보세요.

추론 전 단색에 가깝거나 매우 어둡거나 밝은 이미지 등 명확히 부적합한 입력을 검사합니다. 이 검사는 주차장 사진인지 의미를 이해하는 별도 인식 모델이 아닙니다. 복잡한 무관 이미지, 가림, 잘못 고른 주차칸은 검사에 통과할 수 있으므로 실제 사진과 영역을 사람이 확인해야 합니다. 품질 기준은 주차장마다 검증하고 과도하게 거절하지 않는지 함께 살펴봅니다.

품질 문제로 추론을 생략한 칸, 최고 예측 확률이 판정 기준보다 낮은 칸, 두 확률이 같은 칸은 `확인 필요`이며 빈자리 수에 포함하지 않습니다. 모델의 출력 확률은 실제 정확도나 보장된 신뢰도가 아닙니다. 잘못된 클래스 연결, 세 개 이상 클래스, 유효하지 않은 확률은 오류로 처리합니다.

## 평가 기록과 내보내기

사진의 SHA-256으로 같은 사진을 식별합니다. 같은 사진을 다시 분석·저장하면 기존 평가를 갱신하며 여러 독립 시험 사진처럼 표본 수를 늘리지 않습니다. 이전 버전의 사진 해시가 없는 기록은 출처가 불완전한 과거 기록으로 구분합니다. 다른 압축 파일로 저장한 동일 장면은 바이트 해시가 달라질 수 있으므로 촬영 묶음 단위의 중복 관리도 필요합니다.

내보낸 결과에는 실제 분석 완료 시각, 모델 식별 정보, 사진 식별 정보, 영역, 판정 기준과 전처리·품질 정보를 남깁니다. CSV의 기본 `frame_id,slot_id,truth,status,confidence,source` 열은 Python 평가 도구와 호환되며 추가 열은 재현에 필요한 정보입니다. 분석 완료 시각과 결과 파일 다운로드 시각은 구분합니다.

## 검증 범위

단위 테스트는 품질 검사, 영역 검증, 확률 판정, 파일 입력 검증, 평가 기록과 내보내기 계산을 확인합니다. 이 테스트를 모델의 주차 인식 정확도로 보고하지 않습니다. 개별 주차칸 정확도, 실제 전체 사진 네 칸의 빈자리 수 일치율, 차량을 빈자리로 안내한 오류를 각각 실제 정답으로 평가합니다.

320px·390px 화면 확인과 모바일 실기기 검증은 다릅니다. iPhone Safari·Android Chrome에서 모델 로딩 시간, 분석 시간, 메모리와 취소 동작을 별도로 확인해야 합니다. 기본 CPU 실행을 사용하며 실제 기기에서 측정하지 않은 성능 수치를 제시하지 않습니다.
