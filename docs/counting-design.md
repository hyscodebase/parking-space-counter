# 주차칸별 분류로 차량 수 세기

## 처리 방식

1. 주차장 사진을 촬영하거나 선택합니다.
2. 주차칸에 맞춘 사각형을1~100개 지정하거나 같은 카메라의 프로필을 불러옵니다.
3. 각 사각형 전체를224×224 RGB로 잘라 기존 이진 Teachable Machine 모델에 넣습니다.
4. `빈자리 / 사용 중 / 확인 필요`로 판정합니다.
5. **사용 중인 칸의 수를 차량 수로 합산**합니다.

기존 v2 가중치는 유지합니다. 차량 수별 새 분류 모델이나 차량 탐지기는 추가하지 않습니다. 주차 위치를 자동으로 찾는 기능도 아니므로 첫 사진에서는 사람이 영역을 맞춥니다.

## 수량 표시

`확정 차량 수 = 사용 중 칸 수`, `가능한 최대 수 = 사용 중 칸 수 + 확인 필요 칸 수`입니다.

| 판정 예시 | 해석 |
| --- | --- |
| 사용 중7칸·빈자리3칸 |차량7대|
| 사용 중7칸·빈자리1칸·확인 필요2칸 |확인된 차량7대, 범위7~9대|
| 사용 중0칸·확인 필요2칸 |확인된 차량0대, 범위0~2대. 차량이 없다고 확정하지 않음|

숫자는 규칙 설명용이며 고정된 앱 시연 결과가 아닙니다. 공개 예제도 매번 실제 모델로 추론합니다. 모델 자체가 틀릴 수 있으므로 이 범위도 현실의 수량을 보장하는 통계적 신뢰구간은 아닙니다.

## 집계 전제

- **지정한 주차칸 안**만 셉니다. 통로나 영역 밖 차량은 제외합니다.
- **한 칸에 차량 한 대**라는 전제입니다. 여러 칸에 걸친 한 차량이나 한 칸의 여러 차량은 단순 합산에 맞지 않습니다.
- 각 영역은 서로 다른 실제 주차칸 하나를 포함해야 합니다. 동일 영역은 중복 지정할 수 없고 큰 겹침은 경고합니다.
- 카메라 위치·각도·줌·사진 크롭이 바뀌면 영역을 다시 맞춥니다. 저장한 프로필이라고 현재 사진과 정렬이 보장되지는 않습니다.
- 기존 모델은 주간 PKLot 자료로 학습했습니다. 다른 현장·심한 가림·야간은 별도 검증이 필요합니다.

영역 수를 늘려도 모델이 더 많은 장면을 학습한 것은 아닙니다. 한 칸의 오류도 전체 수량을 바꾸므로 실제 현장의 수량 일치율을 따로 평가합니다.

## 화면과 모바일

중심 흐름은 **사진 → 주차칸 확인 → 차량 수**입니다. 프로필·모델·판정 기준 등 부가 설정은 필요할 때 펼칩니다. 모바일 촬영 버튼은 후면 카메라를 요청하는 파일 입력을 사용하고 갤러리·파일 선택은 별도 버튼으로 제공합니다.

촬영 화면과 사진 형식·카메라 지원은 기기·브라우저에 따라 다릅니다. 반응형 화면 확인이 실제 iPhone·Android 촬영·처리 속도 검증을 대신하지 않습니다. 실시간 영상은 분석하지 않습니다.

## 검증 구분

코드 검사는 가변 영역 수, 중복 ID·좌표 차단, 확률 판정, 불확실 수량 범위와 입력 파일 처리를 확인합니다. 모델 정확도를 입증하는 검사는 아닙니다.

기존 전체 사진30장·고정4칸120/120 정답과 미학습 시점10장·고정4칸37/40 정답은 보존합니다. 이를100칸 지원의 정확도로 바꾸어 표기하지 않습니다. 새 가변 영역 진단은 기존에 관찰한 사진에서 대상 칸을 확대한 추가 점검이며 새로운 독립 최종 시험으로 부르지 않습니다.

추가 진단은 UFPR04의 기존3개 날짜에서 사진20장·주차칸559개를 평가했습니다. CPU240초 예산에 따라 예제를 먼저 확인하고 나머지는 촬영시각순으로 진행했습니다. 결과를 보고 유리한 사진을 골라낸 시험은 아닙니다.

| 추가 진단 지표 | 결과 |
| --- | --- |
| 칸별 정답 |551/559 (98.57%)|
| 확인 필요 없이 차량 수까지 정확 |13/20장 (65%)|
| 확정 차량 수만 정답과 일치 |17/20장. 확인 필요가 있는 사진도 포함하므로 정확한 수량 확정과 다름|
| 안내한 수량 범위에 정답 포함 |17/20장|
| 빈 칸을 차량으로 판단 |3칸|
| 차량을 빈자리로 판단 |0칸|
| 확인 필요 |5칸|

전체 칸으로 넓힌 미학습 카메라 평가는 수행하지 않았습니다. Pillow 리사이즈와 브라우저 Canvas에는 픽셀 차이가 있을 수 있습니다. 자세한 [진단 보고서](counting-validation.md)와 [수치 JSON](counting-validation.json)을 함께 보세요.

공개 예제에는 PKLot 실제 사진과 주석이 있는28개 주차칸의 **위치만** 제공합니다. 앱에 정답 수량을 넣지 않고 실제 추론값을 사용합니다. 이번28칸 진단에서 실제 차량은3대였고 모델은 사용 중3칸·빈자리24칸·확인 필요1칸으로 판단했습니다. 따라서 화면은 `확인된 차량3대`, 범위 `3~4대`로 해석해야 하며 과거4칸의 완전 일치 결과로 대신하지 않습니다.
